# Synta v89

## Shared source and releases

This is the operator-owned repository, separate from alexzhang13/rlm.
All managed hosts poll Mantiee/rlm, branch v100-rtx-reconnect. The installer resolves
an immutable SHA and checks the release inventory. Source snapshots are readable by
Synta; model-authored suggestions do not automatically replace host executable code.
Updates retry around exclusive training. A source snapshot is not proof that every
role or running process has adopted it. Check package version and host receipts.

## Availability

Chat now checks the helper's resource guard before selecting it. Transport failures
before generation can select another qualified helper or the accepted local/CPU backend.
Pinned Windows advisory research remains available while V100 trains. A failed plain
read-only chat question can be reopened with its original failure archived; commands
are never automatically replayed.
If all admitted backends are unavailable, the saved request waits rather than failing
after two attempts. No automatic replay is promised after tools have already executed.
Guard diagnostics distinguish stale heartbeat, contract mismatch and resource pressure.
Freshness can use the monitor's own monotonic age, avoiding cross-host clock differences.
The inherited legacy wall-clock contract still refuses stale data.

Windows bootstrap repairs the proxy in the visible console, independently of an older
background model downloader. Scheduled updater stdout/stderr is retained in
ai-v100-helper/logs/managed-update-run.log. A successful registration is not a successful
model admission. An active request defers replacement; pressure protection remains.

Main recovery can retire an old updater downloader only after checking its systemd
cgroup for exclusive jobs and its installer markers. It leaves V100 training in a
separate service intact. The one-minute mission watchdog remains independent.

## Planning and learning

The model can update short and medium plans through set_plan. A new asynchronous planner
checks evidence and failures periodically, without changing the operator's long-term
goal or authorization limits. Versioned plans contain measurable next steps; they do
not prove execution, accepted optimizer updates, profit or payment.

Wikipedia passages committed to the local index are available to RAG while import
continues. Import progress includes compressed bytes, current-part percentage and a
measured ETA. There is no reliable whole-import ETA without complete part measurements.
The archive is retrieval knowledge; it is not automatically weight training. A failed
small n-gram pilot gets one new versioned attempt, preserves its old evidence, and
sizes its byte context to complete examples instead of truncating them.

## Resources

Main CPU admission can use up to sixteen concurrent bounded jobs when core and RAM
headroom permit, instead of a fixed four-slot ceiling. The dedicated node uses its
available GPU and bounded fixed-kernel CPU pool, with boot services and reconnects.
Accepted CPU chat can use up to eight threads under its existing RAM/identity guards.
Idle resources remain idle when no valid work/data are available; busy loops do not
constitute learning. Physical speed, model admission and revenue require host evidence.

These update code and services, retaining accepted weights, private ledgers and archives.

## v90 model migration

The managed channel prepares explicit October 2026 candidates: Windows fast roles use Gemma 4 E2B/E4B Q4; planning compares Qwen3.8 27B Q4 and Gemma 4 26B-A4B Q4. The dedicated RTX 3060 Ti prepares Gemma 4 E2B first, with E4B admitted only after full GPU residency and independent task checks. Native Debian acquisition prepares Gemma 4 E2B and Qwen3.8 27B GGUF; downloading does not promote a native master.

Qwen3.5, Qwen3.6 and GPT-OSS profiles stay archived and are excluded from production routing under the installed v90 policy. Metadata-only probes may read the former researcher configuration to discover the new inventory; no historical-model generation is used by the new qualification panel. Current candidates must pass every accounting/arithmetic/evidence case. Timing chooses among passing roles and does not establish broad intelligence or profit.

Accepted V100 learner weights and the active training cycle are retained. They are distinct from the larger advisory planner. CPU offload is permitted for the declared Gemma MoE role; it is not claimed faster without measurement. No 120B/180B or 500K-context activation is implied.

The dashboard table “Models by computer and role” reads host receipts. Qualified, downloaded, retired and unknown are separate states; qualification never proves current serving. Updaters on each host follow the same immutable channel independently and defer active work before replacement.
